AIと会話するとき中で何が起きているか：「量子力学はなんですか？」が回答になるまで

October 24, 2026 | 3 Minute Read

全体像

質問文は「分割 → ベクトル化 → 層を重ねる → 1語選ぶ」の4段階を通り、選んだ1語を末尾に足して、終了まで繰り返されます。

この記事は、「量子力学はなんですか？」という質問を例に、入力から回答の完了までを順に追います。説明に使う数字は、すべて仮のものです。

  • ベクトルは4次元（実際は数千次元）
  • 層は3つ（実際は数十層以上）
  • 注意のヘッドは1つ（実際は複数）
  • トークンは「量子 / 力学 / は / なんですか / ？」の5つ（実際の区切りはモデルによって違う）

先に出てくる用語を、短く説明します。詳しくは手順3で扱います。

  • 注意：各位置が、前の位置を見て情報を集める処理です。
  • FFN：各位置のベクトルを、その位置だけで加工する処理です。
  • K・V：注意で使う、「自分は何か」を表すベクトル（K）と、「運ぶ中身」を表すベクトル（V）です。
  • 位置：入力の中の、トークン1つ分の場所です。

層数やヘッド数などの実例は、公表されている目安です。モデルごとに違い、非公開のものも多くあります。

図1：4つの箱を左から右へ進みます。選ばれた語は新しい位置として2番目の箱に戻り、終了トークンが選ばれるまで続きます。

学習済みで固定のものと、毎回変わるもの

回答中に変わるのは、入力から計算される途中の数字だけです。学習で決まったパラメータは、1つも変わりません。

区分 具体例
固定（学習で決まる） 埋め込み表、各層のQ・K・V用の重み、FFNの重みと偏置、出力行列
毎回計算される 各位置のベクトル、Q・K・V、注意の比率、各層の出力、点数、確率
  • パラメータは最初は乱数で、訓練で少しずつ調整されます。誤差を測り、逆伝播（誤差から、各パラメータをどちらにどれだけ直すかを逆向きに求める方法）で各パラメータの寄与を求め、小さく直す作業を何度も繰り返します。
  • 層ごとに重みは別です。層1と層2は、同じ形の別の計算をします。
  • 注意の比率（0.35など）は、乱数から反復して求めるものではありません。固定の重みを使って、入力のたびに一度だけ計算します。
  • 事前学習で得られるのは、具体的な比率ではなく、「どう探すか」という通用する規則です。通用する範囲は、訓練データの範囲に左右されます。
  • 訓練の最中は、全位置が同時に「それぞれの次のトークン」を予測します。未来の位置は遮罩で見えません。
  • 微調整や、RLHF（人間の評価を使って答え方を調整する訓練）では、重みが再び変わります。一方、提示文に例を入れる（少数ショット）だけでは重みは変わらず、入力が変わるので出力が変わります。

手順1　分割（トークン化）

モデルは文字を読めないので、文を語彙表にある「トークン」に切り分け、番号に直します。

例（番号は仮）：量子 → 38721、力学 → 5520、は → 9、なんですか → …、？ → …。トークンは、1文字、1語、語の一部のどれにもなります。語彙表の大きさは、GPT-3で約5万です。この段階は表を引いて切るだけの機械的な処理で、理解は入っていません。

  • 実際のチャットでは、システムの指示や、発言の開始・終了を示す特別なトークンが前後に付きます。
  • そのため、予測の起点になる最後の位置は、「？」ではなく「ここからアシスタントが答える」を示す特別なトークンです。この記事の例は、説明を簡単にするため「？」を最後としています。
  • 「量子力学」が1つのトークンになるモデルもあります。その場合は、分割されず最初から1つとして扱われます。

手順2　ベクトル化（埋め込み）

トークン番号で埋め込み表を引き、数字の列（ベクトル）に変えます。ここから先は、すべて数字の計算です。

例（4次元）：量子 → (0.2, −0.8, 0.5, 1.1)、力学 → (0.3, −0.7, 0.4, 0.9)、は → (−0.1, 0.0, 0.2, 0.1)。実際のモデルでは数千次元以上で、GPT-3は12288次元とされています。意味の近い語は近くに並び、「国王 − 男 + 女 ≒ 王妃」のような関係も、距離として表れます。ただし、語の意味そのものが数字に入っているのではなく、訓練で得られた統計的な規則です。

位置情報も加えます。これがないと、「量子力学はなんですか」と「なんですか量子力学は」を区別できません。方式はモデルによって違います。

モデルごとに違う

  • 次元数、語彙表、座標系（各数字の意味）が違います。
  • 構造が同じモデルを、乱数の初期値だけ変えて学び直しても、数字は互換になりません。
  • そのため、あるモデルのベクトルを別のモデルに入れても意味をなしません。検索用の埋め込みAPIもモデルごとに別の空間で、モデルを変えたら保存済みのベクトルを作り直します。
  • 一方、意味の近さという構造は、モデルが違っても似る傾向があると報告されています。
  • ベースモデルから派生したモデルは、語彙表と埋め込みを共有することがあります。

固定か、変わるか：2種類のベクトル

  初期ベクトル 各層のあとのベクトル
同じトークンなら 同じ 文脈で違う
由来 埋め込み表を引く 層ごとの計算
訓練が終わったら 固定 入力のたびに計算

例えば「アップル」という同じトークンでも、注意を通ると、「パイを焼いた」の文では果物寄り、「新製品を出した」の文では会社寄りのベクトルになります。これが右の列の話です。初期ベクトルの表自体は、微調整で更新されることがあります（LoRAなどでは凍結することが多い）。

手順3　層1の中身（注意とFFN）

1層は「注意で位置どうしが情報を混ぜ、FFNで各位置が加工する」2段で、どちらも元のベクトルへの足し戻しを伴います。

注意：誰を見るかを、その場で計算する

  1. 各位置のベクトルに、学習済みの重み行列を掛けて、Q（何を探すか）、K（自分は何か）、V（運ぶ中身）を作ります。
  2. 「？」のQと、各位置のKの内積を取り、点数にします。
  3. 点数をsoftmaxで比率にして（大きい点数ほど大きな比率に、全部足すと1になるよう直す計算です）、その比率でVを足し合わせます。これが注意の出力です。

「？」のQを(1, 2)とした仮の計算です（Q・Kは2次元）。

相手 K 内積 ÷√2 softmax後
量子 (1, 0) 1 0.71 0.06
力学 (2, 1) 4 2.83 0.51
は (0, 1) 2 1.41 0.12
なんですか (0, 0.5) 1 0.71 0.06
？ (1, 1) 3 2.12 0.25

合計は1.00です。「力学」に最も多く注意が向くので、Vの足し合わせでは「力学」の成分が約半分を占めます。この数字は説明用です。実際の比率は層とヘッドごとに違い、自分自身への注意も含みます。

遮罩：見えるのは自分より前だけ

生成モデルでは、各位置から見えるのは自分より前の位置だけです。「量子」の位置は自分しか見えず、重みは1.0になります。「力学」の位置は、「量子」と自分だけを見ます。「？」だけが、5つすべてを見ます。

  • 後ろの語は見えませんが、後ろの位置が前を見ます。「量子力学」という組み合わせは、「力学」の位置で整理されます。
  • 質問文だけで見れば「量子」は手がかりが少ない位置です。ただしチャットでは、その前にシステムの指示などのトークンがあり、それらは見えます。
  • 前と後ろを両方見られるのは、BERTのようなエンコーダ型のモデルです。
  • 後ろの語が来ても、前の位置のK・Vは変わりません。前の位置は後ろを見ないので、同じ入力から同じ値が出るからです。そのため、一度計算したK・Vを保存して使い回せます（KVキャッシュ。図7を参照）。

多頭：同じ入力に、複数の見方を同時に走らせる

1つの層の中に複数のヘッドがあり、それぞれ独立したQ・K・V用の重みで注意を計算します。結果は連結し、行列を掛けて元の次元に戻します。同じ文を複数人が別々の観点（誰が何をしたか、いつか、など）で読み、あとで結果をまとめるようなものです。

  多頭（ヘッド） 層
増やす方向 横（並列） 縦（直列）
入力 同じ層の同じ入力を全ヘッドが受ける 1つ下の層の出力
役割 同時に複数の関係を捉える 結果を積み上げ、情報を遠くへ伝える
重み ヘッドごとに別 層ごとに別

総ヘッド数は「層数 × 1層のヘッド数」です。原論文のモデルは6層で各層8ヘッド、GPT-3は96層で各層96ヘッドとされています。1ヘッドの次元は、全体の次元をヘッド数で割った小さな値です。そのため、ヘッドを増やしても計算量はほぼ変わりません。

足し戻しと正規化

注意の出力は、元のベクトルに足し戻します（残差接続）。そのあと、数字の大きさをそろえます（正規化）。元の情報を残したまま新しい情報を上乗せする仕組みなので、層を重ねても、自分の位置の情報は消えません。

足し戻しは、数字ごとの足し算です。元のベクトル x の1番目と、注意の出力 a の1番目を足し、2番目どうし、3番目どうし、4番目どうしも同じように足します。

図2：上の2段を数字ごとに足したものが、一番下の結果です。

足し戻す意味は、次のとおりです。

  • a は、「元の値を、周囲の情報でどう直すか」という修正量です。足すので、元の値が土台として残り、a の分だけ動きます。
  • a が正なら増え、負なら減ります。2番目は 0.4 が −0.1 で 0.3 になり、3番目は −0.2 が 0.2 で打ち消されて 0.0 になります。
  • 足し戻さず a だけを次に渡すと、元の語の情報が消えてしまいます。
  • 層を重ねても元の情報が残ります。また、訓練のとき誤差の信号が元の経路を通りやすくなることも知られています。
  • この数字は仮です。実際は数千次元で、同じ足し算を全部の次元で行います。a の値は、注意の計算から出てきます。

FFN：各位置のベクトルを個別に加工する

FFNは、他の位置を見ずに、各位置のベクトルを同じ重みで個別に変換します。次元を4倍程度の中間まで広げ（4 → 16 → 4）、元の次元に戻します。

神経元1個の計算例です。入力は(2, 3, −1)、重みは(0.5, 0.1, 0.4)、偏置は0.2とします。

手順 計算 結果
① 重みを掛ける 2×0.5、3×0.1、−1×0.4 1.0、0.3、−0.4
② 足す 1.0 + 0.3 − 0.4 0.9
③ 偏置を足す 0.9 + 0.2 1.1
④ 活性化 負なら0、正ならそのまま 1.1

重みと偏置が、訓練で調整されるパラメータです。同じ入力に対し、重みの違う神経元を何千個も並べて同時に計算すると、出力は数千個の数字（新しいベクトル）になります。

活性化がないと、何層重ねても全体が1回の掛け算と足し算にまとまってしまいます。「負なら0」のような非線形の処理を挟むから、層を重ねる意味が生まれます。

FFNが必要な理由は、次のとおりです。

  • 注意は情報を集めて混ぜるのは得意ですが、集めたものを加工する力は弱いです。注意は会議で他の人の意見を聞くこと、FFNは聞いた内容を持ち帰って考えることにたとえられます。
  • 活性化により、「この特徴とこの特徴が同時にあるときだけ反応する」といった判断ができます。
  • 事実のような知識が蓄えられている場所だという有力な仮説がありますが、確定していません。
  • 標準的なTransformerでは、パラメータの約3分の2を占めます。

層1の出力

層1の出力は「新しいV」ではなく、各位置の新しいベクトルです（入力と同じ次元）。「？」の位置の仮の計算は、次のとおりです。正規化の位置はモデルによって違うので、省いています。

手順 結果
入力 x (0.1, 0.4, −0.2, 0.6)
注意の出力 a (0.3, −0.1, 0.2, 0.2)
x + a（足し戻し） (0.4, 0.3, 0.0, 0.8)
FFNの出力 f (0.1, 0.2, −0.3, 0.1)
足し戻して出力 (0.5, 0.5, −0.3, 0.9)

Vは、注意が新しく作るものではありません。入力に重みを掛けて作る、材料の1つです。新しいQ・K・Vが作られるのは、層2です。

FFNは個別なのに、階層ができる理由

FFNは単語ごとの処理ですが、そのベクトルは、直前の注意で他の語の情報を含んでいます。注意が混ぜ、FFNが整理することを、層ごとに交互に繰り返します。層が進むたびに、前の層で整理された情報を材料に、さらに関係を見ます。

これが、「語 → 句 → 文 → 主旨」と抽象度が上がっていく仕組みです。ただし、この階層は画像認識の「辺 → 形 → 部品 → 全体」からの類推です。実際は、役割がきれいに分かれず、複数の処理が混在することが研究で示されています。各層が何をしているかは、確実には分かっていません。

並列と順番：同じ層の中は同時、層をまたぐと順番

5つの位置は、各層の中では同時に計算されます。層をまたぐときだけ、「下の層が全部終わってから」という順番になります。

  • 層1の「？」は、入力のベクトルだけを使います。他の位置の計算を待ちません。
  • 層2の「？」は、層1の全位置の出力を材料にします。そのため層1が終わってから始まります。
  • つまり「？」が待つのは、前のトークンの全処理ではなく、前の層の結果がそろうことです。同じ層の中では、他の位置を待ちません。
  • 層の入力は1つ下の層の出力で、層の出力は、その層が作る新しいベクトルです。同じ層の出力は、同時に計算している最中でまだ存在しないので、材料にできません。
  • 同じ層の位置を同時に計算できるのは、Q・K・Vの作成が位置ごとに独立しているからです。全位置を1つの大きな行列にまとめて一度に計算できるので、GPUに向いています。語を1つずつ順に読む従来の方式（RNN）では、前の語の処理が終わるまで次に進めませんでした。この弱点を、これで解消しました。
  • 例外：回答を作る段階（デコード）では並列になりません。次のトークンは、直前に選んだトークンが決まってからでないと計算できないので、1つずつ順番に生成されます。回答が逐語的に出てくるのは、この性質によるものです。

図3：同じ層の中の5位置は、同時に計算されます。「？」の層2の計算は、層1の全位置の出力（色つきの線）がそろってから始まります。

層を重ねる：同じ構造を、別の重みで

層2以降も、層1と同じ手順を、別の重みで、1つ下の層の出力を入力にして繰り返します。

  • 層2の入力は、層1の出力（5位置分のベクトル）です。層3は層2の出力を、層4は層3の出力を入力にします。
  • 構造は同じですが、重みは層ごとに別で、学習で別々に調整されています。
  • 材料の中身も違います。層1の入力は単語そのものに近いベクトルですが、層2の入力は、すでに周囲の情報が混ざったベクトルです。そのため、同じ「？」でも、層2では層1と別の観点で他の位置との関係を計算します。
  • 層数は、GPT-1が12層、GPT-3が96層とされています。最近のモデルの層数は、多くが非公開です。

図4：層1で「を」が「りんご」を取り込みます。破線のように、「食べた」は層1でも「りんご」を直接見られます。層2では、すでに「りんご」の情報を含む「を」も材料にできます。層を重ねるのは、範囲を広げるためではなく、整理済みの情報を重ねるためです。

見る範囲は、層ごとに広がるのか

標準的な（全結合の）注意では、見られる範囲は全層で同じです。生成モデルなら、どの層でも自分より前の全トークンを見られます。層1でも、遠くの語に直接注意を向けられます。

層ごとに変わるのは、範囲ではなく材料の抽象度です。層2以降で見るのは、前の層で整理されたベクトルです。

  • 例外：スライディングウィンドウ方式では、各層は直近の一定個数だけを見ます。ただし層を重ねると情報が間接的に伝わるので、L層でおよそ「L × 窓の幅」先まで届きます。
  • 例外：局所的な注意と全体の注意を、層ごとに交互に使うモデルもあります。
  • 同じ層の中でも、ヘッドによって近くの語ばかり見るもの、遠くの語を見るもの、先頭トークンに向くものが混在します。浅い層は近くを見るヘッドが多い傾向が観察されていますが、設計上の決まりではありません。
  • 商用モデルがどの方式かは、多くの場合公開されていません。

図5：下から上へ、手順①②③の順に進みます。最上層では「？」の位置だけが確率の計算に使われ、選ばれた語は右の矢印で入力の末尾に戻ります。

最後の層と最後の位置

予測に使うのは、最上層の最後の位置のベクトルだけです。他の位置の最上層の出力は、予測に使いません。

次の2点は区別して考えます。

  • 最後の位置が使うもの：最上層でも「？」は、全位置のK・Vを参照します。このK・Vは、1つ下の層の出力から作ります。
  • 他の位置の最上層の出力（注意の出力やFFN）：予測にも、今後の計算にも使いません。そのため、省く実装があります。実装によっては、全位置分を計算して最後の位置だけを使います。

学習時は事情が違います。全位置が、それぞれの次の語を予測するので、最上層でも全位置の出力が必要です。推論時に最後の位置だけを使うのは、「？」の次の語、つまり回答の最初を知りたいからです。

最後の位置のベクトルは、前の層を通じて前文全体の情報を取り込んでいます。そのため、「前文をもとに予測する」と「最後のトークンの位置から予測する」は、実質的に同じことを指します。単独のトークンの意味だけで予測しているのではありません。

入力を読み込む段階（プレフィル）でも、途中の層は全位置を計算します。その結果のK・Vを保存して、あとで使い回します。

出力の変換：ベクトルから「次の1語」へ

最後の位置のベクトルに出力行列を掛けて、語彙全体の点数を出し、softmaxで確率にして、抽選で1語を選びます。

仮の例です。最後の位置のベクトルを h = (0.5, 0.5, −0.3, 0.9) とし、出力行列の各列は1つのトークンに対応します。点数は、h とその列の内積です。

トークン その列の重み 内積（点数） 確率
量子 (1.0, 0.5, 0.0, 1.5) 2.10 67%
物理 (0.8, 0.2, 0.1, 1.0) 1.37 32%
炒菜 (−1.0, −0.5, 0.5, −1.0) −1.80 1%

「量子」の点数は、0.5×1.0 + 0.5×0.5 + (−0.3)×0.0 + 0.9×1.5 = 2.10 です。softmaxは、点数を指数にして（8.17、3.94、0.17）合計で割ります。実際は、列が語彙の数だけ（約5万〜数十万）あります。この表は候補3つだけの仮の例なので、確率の合計が100%に見えます。

図6：左の色つきの列が、最後の位置のベクトルです。出力行列の各列との内積が点数になり、softmaxで確率に変わり、抽選で1語が選ばれます。

注意ではない

内積を使う点は似ていますが、役割が違います。

  注意 出力の変換
相手 同じ文の中の他の位置 語彙の全トークン（約5万個）
Q・K・Vを作るか 作る 作らない（掛け算1回）
内積のあと 比率でVを足し合わせ、新しいベクトルを作る 点数を確率にして終わり
結果 文脈を取り込んだベクトル 次に来るトークンの確率
  • 出力行列も学習済みで、推論中は固定です。
  • 入力の埋め込み表と同じ数字を（転置して）共有するモデルもあります。その場合は、「最後のベクトルが、どのトークンの埋め込みに近いか」を測っているとも言えます。共有しないモデルもあります。
  • 使うのは最後の位置のベクトルだけです。

抽選

確率が最も高い語を、必ず選ぶとは限りません。確率に応じて抽選します。「温度」はsoftmaxの前に点数を割って、確率の偏りを強めたり弱めたりします。top-pは、確率の高い候補に絞って抽選します。同じ質問でも答えが毎回変わるのは、この抽選のためです。

繰り返し：1語ずつ生成して終了まで

選ばれた語を末尾に足し、次の1語を同じ手順で作ることを、終了トークンが選ばれるまで繰り返します。

  1. 「量子」が選ばれた（図6の仮の例では67%）。末尾に足す。
  2. 新しい位置の1つだけを計算する。過去の位置のK・Vは、保存したキャッシュから使う。
  3. 次の語を選ぶ。例：力学（58%）→ は → 、→ …
  4. モデルが、終了を示す特別なトークンを選んだら止まる（長さの上限でも止まる）。
  5. 選ばれたトークンを文字に戻し、順に画面に表示する。

KVキャッシュとプレフィル・デコード

  • プレフィル：質問全体を読む段階です。全位置を並列に計算し、各層のK・Vを保存します。
  • デコード：回答を作る段階です。新しい1トークンだけを計算し、過去のK・Vはキャッシュを使います。1語ずつ順番になります。
  • キャッシュがないと、1語生成するたびに、前の位置のK・Vを全部作り直すことになります。キャッシュを使っても、新しい位置が、見える全位置と注意を計算する点は変わりません。

なぜ並列なのに、前の語のK・Vを使うのか

「並列に計算する」ことと、「前の語のK・Vを使う」ことは、別々の話です。

  • 並列：質問を読む段階（プレフィル）では、全位置を同時に計算できます。位置どうしの計算が、互いの結果を待たないからです。
  • K・Vを使う理由：注意は、各位置が前の位置を見て情報を集める処理だからです。並列かどうかに関係なく、見る相手のK・Vが材料として必要です。
  • キャッシュが効く理由：回答を作る段階（デコード）では、毎回、末尾に1語だけ増えます。前の位置は後ろを見ないので（遮罩）、後ろに新しい語が来ても、前の位置のK・Vは変わりません。同じ値を毎回作り直すのは無駄なので、保存して使い回します。
  • 保存するのはK・Vだけです。過去のQは、その位置の注意を計算するためのもので、あとの位置では使わないので捨てます。
  • キャッシュは層ごとに持ちます。文脈が長いほど、メモリを使います。

図7：ステップ1で5位置のK・Vを同時に計算して保存します。ステップ2以降は、新しい1位置だけを計算し、その位置が保存済みのK・Vをすべて見ます。

関連する疑問

仕組みに関するよくある疑問と、その答えです。この節の数字や研究名は、記憶に基づく目安で、出典を確認したものではありません。

「再調査して」で直ることが多いのはなぜか

2023年頃の、ツールを持たないChatGPTは、「本当ですか？」と聞かれても、「その問いの後には『はい』が続きやすい」という統計だけで「はい」と答えがちでした。検証の手段がなかったからです。幻覚は偶発的な不具合ではなく、次のトークンを予測するという仕組みから出てくる性質です。

今は、次の点が違います。

  • 外部ツール：検索や、検索した資料を渡して答えさせる方式（RAG）で、実際に裏を取れます。訂正の根拠は、モデルの記憶ではなく、外から取った情報です。
  • 生成より検証が易しい：最初の回答がコンテキストにあるので、矛盾を点検できます。推論モデルは、この点検を思考の途中で行います。
  • 学習方法の変化：当てずっぽうを奨励せず、「わからない」と言えることを評価する方向です。
  • 再生成：2回目は別の抽選になります。誤りが偶然なら、正答に寄ることがあります。

注意点があります。

  • 「ほとんどの場合」は条件付きです。ツールなしで、知識の薄い領域では、別のもっともらしい誤答が出るだけのことがあります。
  • 迎合：疑われると、正しかった回答を撤回するモデルもあります。
  • 「確認しました」と言うだけで、実際には確認していないことがあります。ツールの呼び出しや、出典URLの有無を見ます。
  • 実務では、「一次情報のURLを付けて再確認して」と頼み、そのURLを自分で開くのが安全です。

最近のAIで変わった点

核（Transformer、次トークン予測、統計的パターン学習）は同じです。変わったのは、周りの仕組みと訓練です。

  • 推論モデル：回答の前に長い思考過程を生成し、検算や見直しをします。正解を機械的に判定できる問題（数学、コード）で強化学習する方法が広がりました。
  • ツール使用とエージェント化：コード実行、検索、ファイル操作などを組み合わせ、複数ステップの作業を進めます。MCPのような、ツール接続の標準規格も整ってきました。
  • マルチモーダルの統合：1つのモデルが、文章、画像、音声、動画を扱えます。
  • 長いコンテキスト：数十万〜100万トークン規模の入力を扱えるモデルがあります。
  • 不確かさの扱いと内部理解の研究：「わからない」と答える訓練が進みました。モデル内部に「この対象を知っているか」を判定する仕組みがあり、その誤作動で幻覚が起きることが示されています。
  • 攻撃面：画素を改変する対抗サンプルは残っています。実害が大きいのは、Webページやファイルに紛れた指示でツールを使うAIを操る、プロンプトインジェクションです。

幻覚はゼロになっていません。ツールなしで、知識が薄い領域の質問をすると、今でも自信満々の誤答が出ます。

100万トークンの文脈では、全部と計算するのか

標準的な（全結合の）注意では、各トークンのQが、見える範囲の全トークンのKと点数を計算します。

  • 100万トークンのペア数は10の12乗です。遮罩があるので、実際はその約半分です。これをヘッドごと、層ごとに行います。
  • 計算量は入力長の2乗で増えます。128kから100万に伸ばすと、注意の計算は約60倍です。
  • 工夫の例：KVキャッシュ（生成時は新しい1トークンが過去N個と照合するだけ）、FlashAttention（結果は厳密で、メモリを節約。計算量は2乗のまま）、スパース注意とスライディングウィンドウ（一部の位置だけを見る方式）、GQA・MQA（KとVの共有）、線形注意や状態空間モデル（Mambaなど）との併用。
  • 商用モデルの方式は、多くが非公開です。純粋な全結合のままではコストが非現実的なので、何らかの最適化が入っていると考えるのが自然です。
  • 長く扱えることと、全体を同じ精度で使いこなせることは別です。中間部分の情報が使われにくい現象も報告されています。

1回しか出ない事実は覚えられるか

「東京はどこですか？　日本」が訓練データに1回だけあり、類似の質問もない場合、必ず「日本」と答えるとは限りません。むしろ、安定して答えられない可能性のほうが高いです。

  • 1回の更新で動くパラメータはわずかで、他の膨大な例による更新に埋もれます。
  • 出力は確率分布です。「日本」の確率が少し上がっても、他の候補が残ります。
  • 類似の質問がないと、一般化の手がかりもありません。
  • 理論研究（Kalai と Vempala らが知られています。私の記憶で、確認はしていません）では、学習データに1回しか現れない事実の割合が、幻覚率の下限になると示されています。
  • 例外：同じ例を何度も学習させる（エポックを重ねる、ファインチューニングで繰り返す）と、記憶される可能性が上がります。ただし、過学習で他の能力が落ちることがあります。
  • 現実の「東京 → 日本」は、このケースに当てはまりません。「東京は日本の首都」「東京都」など、同じ知識を支える文脈が大量にあるからです。頻度と文脈の多様さが、記憶の確かさを決めます。
